How I work

Habits from 10+ years of building and running production systems.

  1. Measure before you spend.

    The obvious cause of a problem is often the wrong one. Before I put money or engineering time into a fix, I measure where the failures and the costs really are.

  2. Success is the result, not the status code.

    A green dashboard proves little. I define success by the outcome the user needs: the data arrived, the policy was issued, the bill went down.

  3. Cheapest method first.

    Expensive tools are the last step, not the default. Most work does not need them, and the savings add up every month.

  4. A backup is done when the restore works.

    I test restores, write runbooks and run incident drills before anything breaks.

  5. Delete before you add.

    Unused resources and dead code cost money and attention every month. Removing them is often the cheapest improvement there is.

  6. Agents write the code. I own the design and the review.

    I set teams up to work agent-first: repository instructions, shared skills and a model for each task. A person still owns every design decision and every review.
